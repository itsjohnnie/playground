$ guide/overture

Overture

Terminal animation is the oldest form of computer graphics that is still alive. Before pixels there were teleprinters; before shaders there was a cursor, a grid of cells, and the trick of overwriting a character fast enough that the eye believed in motion.

The first edition of this guide taught the fundamentals: frames, buffers, escape codes, spinners. This edition asks a different question. How far can the medium actually go? The answer, it turns out, is general relativity.

Everything that moves on this page is generated at runtime from three primitives:

  • A grid of cells, the terminal's native geometry, roughly 1:2 in aspect
  • A luminance ramp: an ordered string of characters, from faint to dense
  • A clock: time, folded through mathematics into light

No sprites were downloaded. No videos are playing. If you view source, you can take all of it with you.

$ guide/engine

The engine

One renderer draws everything on this page. It is small enough to memorize.

A terminal is a 2D array of cells; each cell holds one character and one color. The whole craft reduces to a single mapping: compute a brightness for every cell, then spend that brightness on a character. Dense glyphs like @ and # carry more ink than · or :, so an ordered string of characters becomes a grayscale.

// The only palette you need const RAMP = ' ·:;=+*#%@' // brightness ∈ [0,1] → one character const shade = b => RAMP[Math.min(RAMP.length - 1, (b * RAMP.length) | 0)] // A screen is just chars + colors, double-buffered class Screen { constructor (cols, rows) { this.cols = cols; this.rows = rows this.chars = new Array(cols * rows).fill(' ') this.colors = new Array(cols * rows).fill('') } set (x, y, ch, color) { if (x < 0 || y < 0 || x >= this.cols || y >= this.rows) return const i = y * this.cols + x this.chars[i] = ch; this.colors[i] = color } }

Below, three wave sources drift through the grid. Their interference pattern is summed per cell, and the sum is spent on the ramp. This is the entire discipline in one demo: field → brightness → character.

Timing

Every demo here runs off a single requestAnimationFrame loop with per-demo frame caps, and each one goes dormant the moment it scrolls off screen. In a real terminal the same principle holds: batch the whole frame into one write, cap your rate, and never draw what nobody is watching.

const demos = new Set() const io = new IntersectionObserver(entries => entries.forEach(e => e.target.demo.visible = e.isIntersecting)) function loop (t) { for (const d of demos) { if (d.visible && t - d.last >= 1000 / d.fps) { d.frame(t / 1000) // compute cells d.render() // one atomic paint d.last = t } } requestAnimationFrame(loop) }

$ guide/gravity

Gravity

How the hero above is made: ray tracing in a spacetime where light falls.

The black hole at the top of this page is not an artist's impression. For every cell of the grid, a photon is launched backwards from the camera and integrated through the gravitational field of a Schwarzschild black hole. Near the hole, light doesn't travel in straight lines. It bends, and photons that pass close enough whip all the way around.

The null-geodesic equation collapses to one line of acceleration. That's the entire theory of the image:

// Schwarzschild photon, units where r_s = 1 // h = |r × v| is conserved angular momentum const h2 = cross(pos, vel).len2() for (let step = 0; step < 120; step++) { const r2 = pos.len2() if (r2 < 1) return CAPTURED // inside the horizon: black if (r2 > 260) return sky(vel) // escaped: sample the stars // all of general relativity, as far as this image cares: const a = -1.5 * h2 / Math.pow(r2, 2.5) vel.addScaled(pos, a * dt) pos.addScaled(vel, dt) if (crossedDiskPlane(pos) && rIn < r && r < rOut) return diskHit(r, φ) // remember where we landed }

Two consequences fall out of the integration for free, with no extra drawing code:

  • The lensed halo. The disk behind the hole is visible above and below the shadow. Those arcs are photons from the far side, bent over the top on their way to you.
  • The photon ring. The thin bright edge hugging the shadow is light that orbited the hole one or more times before escaping into the camera.

The geodesics never change while the camera holds still, so they are traced once at load and cached: each cell remembers where on the disk it landed. Per frame, only the disk's surface is re-shaded. Keplerian rotation (Ω ∝ r−3/2, the inner edge visibly outrunning the rim), turbulent streaks, and relativistic beaming that brightens the side spinning toward you. Ray tracing at film quality, at a cost of arithmetic per cell.

// per frame: re-shade the cached disk hits only const ω = 1.4 * Math.pow(r, -1.5) // Keplerian angular speed const φt = φ - ω * t // material coordinate const heat = Math.pow(rIn / r, 0.9) // hotter toward the edge const turb = 0.75 + 0.35 * Math.sin(3 * φt + r * 1.8) + 0.18 * Math.sin(7 * φt - r * 3.1) const beam = 1 + 0.6 * (x / r) // doppler beaming brightness = heat * turb * beam

$ guide/dimension

Dimension

The grid is flat. Nothing else has to be.

The torus, paid in full

The most famous piece of terminal animation ever written is a donut. This one honors it properly: a parametric torus, spun through two rotation matrices, z-buffered, and lit with a Lambert term against a moving light, so the shading rolls across the surface as it tumbles.

// sweep the surface: θ around the tube, φ around the ring const cx = (R + r * cosθ) const x = cx * (cosB * cosφ + sinA * sinB * sinφ) - r * cosA * sinB * sinθ const y = cx * (sinB * cosφ - sinA * cosB * sinφ) + r * cosA * cosB * sinθ const invz = 1 / (cx * cosA * sinφ + r * sinA * sinθ + K) // z-buffer, then spend the Lambert term on the ramp if (invz > zbuf[i]) { zbuf[i] = invz screen.set(px, py, shade(dot(normal, lightDir))) }

A living planet

One analytic ray–sphere intersection per cell, and the grid becomes a world. The surface is four octaves of value noise sampled on the sphere, so continents wrap seamlessly as it turns. A sun orbits slowly; the terminator crawls across the surface; ice holds the poles; the limb catches a thin rim of atmosphere.

// per cell: does this ray hit the sphere? const b = dot(rayDir, -eye) const d2 = eye.len2() - b * b if (d2 > R * R) continue // miss: space const p = pointOnSphere(rayDir, b, d2) const n = p.normalized() // normal = position const land = fbm3(rotateY(n, t * spin)) // noise on the sphere const lit = Math.max(0, dot(n, sunDir)) // the terminator screen.set(x, y, material(land, lat, lit))

Warp field

Four hundred stars in a cone, divided by their own depth; perspective is just x / z. The throttle breathes on a slow cycle: at cruise the stars are points, and as the field accelerates, each star is redrawn several times along its own motion vector and becomes a streak. Speed is rendered as history.

star.z -= speed * dt const sx = cx + star.x / star.z * focal const sy = cy + star.y / star.z * focal * aspect // draw the streak: the star's own recent past for (let k = 0; k < trail; k++) { const zk = star.z + speed * dt * k plot(cx + star.x / zk * focal, ..., RAMP_TAIL[k]) // '#' → '+' → ':' → '·' }

$ guide/light

Light

Modern terminals speak 16.7 million colors. Character chooses the brightness; color chooses the temperature.

Nebula

Fractal value noise, warped by more of itself (fbm(p + fbm(p))), drifting through time as a third dimension. Density picks the character; a two-stop temperature gradient picks the color, from cold cyan gas to the hot rose of the core. A scatter of hashed stars twinkles through the thin regions.

// domain warping: the cloud shapes the cloud const q = fbm(x * s, y * s, t * 0.10) const d = fbm(x * s + 1.7 * q, y * s + 9.2, t * 0.06) const ch = RAMP_SOFT[(d * d * ramp.length) | 0] const col = palette(d) // cyan → violet → rose

Solar surface

The 1993 DOOM fire algorithm, pointed at a star. Heat is injected at the base, and every cell above steals its value from below, minus a random cooling, with a pixel of side-slip for wind. Convection, radiation and flame licks emerge from four lines of code. Nobody drew a single flame.

// classic doom fire: propagate heat upward for (let y = 0; y < rows - 1; y++) for (let x = 0; x < cols; x++) { const src = (y + 1) * cols + x const cool = (Math.random() * 3) | 0 const dst = src - cols - cool + 1 // wind: drift left heat[dst] = Math.max(0, heat[src] - cool) } // bottom row stays molten

$ guide/resolution

Resolution

A braille character is a 2×4 grid of dots. One cell becomes eight pixels.

Strange attractor

The Lorenz system, three coupled equations that became the original mathematics of chaos, integrated live and plotted into a braille pixel buffer at eight times cell resolution. Three particles start a breath apart and diverge forever; their trails decay like phosphor on a storage scope. The camera orbits the attractor slowly.

// Unicode braille: U+2800 + 8 dot bits const DOTS = [[0x01,0x08],[0x02,0x10], [0x04,0x20],[0x40,0x80]] cellChar = String.fromCharCode(0x2800 | bits) // the weather, in three lines dx = σ * (y - x) dy = x * (ρ - z) - y dz = x * y - β * z

Galaxy survey

Six thousand stars on logarithmic spiral arms, each orbiting at its own Keplerian rate: the inner stars lap the outer ones, which is precisely what keeps the spiral wound. Splatted additively into the braille buffer, warm at the bulge and blue along the arms, it reads like a long-exposure plate that happens to be alive.

// each star owns its orbit const θ = star.θ0 + t * 0.5 * Math.pow(star.r, -1.2) const arm = star.arm * Math.PI // two arms const wind = Math.log(star.r + 1) * 3.1 // spiral winding px = r * Math.cos(θ + arm + wind) py = r * Math.sin(θ + arm + wind) * tilt splat(px, py, star.brightness) // additive

$ guide/chaos

Chaos

Particle systems: hundreds of independent lives, one buffer.

Everything so far has been a field, a formula asked politely for its value at every cell. Particles invert the relationship: state lives in the objects, and the screen is just where they land. The demo below runs a full stellar life cycle on a loop, about eighteen seconds from peace to peace:

  • Quiescence: a star breathes, its corona flickering
  • Collapse: the core contracts and whitens
  • Detonation: six hundred particles on ballistic arcs, plus an expanding shockwave ring
  • Remnant: the debris cools through amber to ember, and a pulsar is left blinking in the wreck
~/supernova · 600 particles · quiescence
// a particle is four numbers and a temperament for (const p of particles) { p.vx *= DRAG; p.vy *= DRAG p.x += p.vx * dt; p.y += p.vy * dt p.heat *= COOLING const speed = Math.hypot(p.vx, p.vy) screen.set(p.x | 0, p.y | 0, shade(p.heat), temperature(p.heat)) } // the shockwave is not particles: it's a circle // of cells, drawn at radius v·t, fading as it thins

$ guide/craft

Craft

What survives contact with a real terminal.

Precompute what doesn't move

The single biggest lesson on this page: the black hole traces half a million geodesic steps once, then animates forever on cached results. Separate what is geometry from what is time. Geometry is paid at load; time should cost almost nothing.

One write per frame

Whether it's process.stdout.write('\x1b[H' + frame) or one canvas pass, assemble the entire frame first and emit it atomically. Flicker is the sound of a frame being drawn in installments.

Respect the cell

Terminal cells are about twice as tall as they are wide. Every circle on this page multiplies its x-axis by the cell aspect before comparing distances; skip that and every planet becomes an egg.

const ASPECT = 0.5 // cell width / cell height const dx = (x - cx) * ASPECT const dy = (y - cy) if (dx * dx + dy * dy < r * r) { /* inside the circle */ }

Leave the room as you found it

Hide the cursor, use the alternate screen buffer, and restore both on every exit path, including the one where the user hits Ctrl-C mid-supernova.

process.stdout.write('\x1b[?25l\x1b[?1049h') // enter const restore = () => process.stdout.write('\x1b[?1049l\x1b[?25h\x1b[0m') process.on('exit', restore) process.on('SIGINT', () => { restore(); process.exit(0) })

Motion is a preference

This page honors prefers-reduced-motion: every demo renders a single still frame and stops. In a CLI, honor --no-animation and NO_COLOR the same way. The animation is the garnish; the information is the meal.
